# سجل تغييرات بوابة الخطط الأسبوعية

## v1.1.0 - 2026-09-29

الحالة: نشطة. اكتمل تصحيح الخطتين وإعادة فحص التصميم؛ كلتا الخطتين `APPROVED` في مرحلة `DESIGN`، والمرحلة التالية هي مراجعة تنظيم المكتبة والنماذج وحاجز الخصوصية.

### قرار الاعتماد

اعتمد المستخدم نتائج المراجعة المستقلة ومسار التنفيذ المرحلي، وطلب تنفيذ مرحلة «إصلاح مواصفة بوابة الخطط نفسها وإصدار Gate v1.1».

### المسار المرحلي المعتمد

1. مراجعة مستقلة للمصادر والبوابة والكود والخطط - مكتملة.
2. إصلاح مواصفة Gate وإصدار v1.1 - مكتملة بهذا الإصدار.
3. تحديث مشغل Gate ومخطط assessment والاختبارات - مكتملة.
4. إعادة Dry Run للخطتين دون تعديلهما - مكتملة؛ الأسبوع الأول `BLOCKED` والأسبوع الثاني `HUMAN_REVIEW_REQUIRED`.
5. تصحيح الخطتين بعد عرض نتائج Dry Run واعتماد المستخدم - مكتملة؛ كلتا الخطتين `APPROVED` في مرحلة `DESIGN`.
6. مراجعة النقل والتسمية والتكرار والنماذج وحاجز الخصوصية - المرحلة التالية، غير منفذة.

### التغييرات الجوهرية

- ثبت هرم المصادر بحسب نطاق السلطة، وجعل خطة القصيم 1448 مرجع الاستحقاق والتوقيت المحلي، ونور قناة حقول وتوثيق لا منشئ استحقاق.
- حُصر تفسير 1447 على أنه 1448 في المواضع المحددة سابقًا داخل جداول خطة القصيم فقط، مع حفظ القيمة الأصلية وسبب التفسير.
- قسمت البوابة إلى `DESIGN`, `PRE_EXECUTION`, `POST_EXECUTION`, `CLOSURE`.
- استبدل نموذج الشدة المفاهيمي بـ`BLOCKER`, `WARNING`, `REVIEW`, `INFO`.
- أضيفت حالات معلومات تمنع اختلاق القيم: `PENDING`, `NOT_MEASURED`, `NOT_APPLICABLE`, `NOT_ASSESSABLE_YET`.
- عُدلت D01 للسماح بالالتقاط المؤقت والأصل الموقع والأداة الحساسة والشاهد المطلوب، مع منع السجل الموازي بلا قيمة.
- عُدلت W01 إلى أولوية تقدم واحدة مع السماح بالأعمال النظامية المستمرة والغياب والانضباط والحالات والمواعيد والخدمات الحدثية والطوارئ.
- عُدلت N01 للفصل بين مسار نور المتوقع في التصميم والإجراء الفعلي بعد التنفيذ.
- عُدلت N03 وV01 للفصل بين غياب القياس وبين الادعاء المختلق.
- أضيف عقد دليل منظم يتطلب locator قابلًا للحل ومراجعًا وتاريخًا وسببًا لغير المنطبق.
- ثبتت سياسة عدم التطبيق الرجعي الجماعي.

### تنفيذ المشغل v1.1

- أضيف schema 2.0 منظم للـassessment.
- يتحقق المشغل من المرحلة، والبصمة، والمراجع المطلوبة لكل قاعدة، ووجود locator، وصحة التواريخ وهوية المراجع.
- يحدد القواعد المتأثرة عند غياب مرجع مطلوب.
- يرفض ملفات assessment القديمة من v1.0 بطريقة fail-closed دون انهيار.
- أضيفت حالات النتائج المرحلية ومستويات الحكم المعتمدة.
- أضيفت 18 اختبارًا آليًا، بينها اختبار يغطي السيناريوهات التشغيلية السبعة عشر المطلوبة، وتعمل كلها من جذر المكتبة.
- تبقى نتائج v1.0 تاريخية، ولا تعدل لإجبارها على المرور.
