# قائمة فحص بوابة الخطط v1.2

هذه القائمة للمراجعة البشرية وفق المرحلة، وتوثق نتائجها وفق schema 2.1 ثم تجمع بواسطة مشغل `1.2.1`. الوجود البنيوي للموضع لا يثبت دعم الادعاء؛ يظل الحكم الدلالي منفصلًا.

## DESIGN

- [ ] للبرنامج الرسمي أو الأولوية الجديدة سند استحقاق أو حاجة فعلية موثقة، ووجوده في نور ليس السند (E01).
- [ ] الفئة والانطباق صحيحان للصفوف 2-6 ولا تستبدل فئة نور العامة فئة المصدر (E02).
- [ ] تقويم الأسبوع والسنة الأصلية والتفسير المحدود موثقة (E03).
- [ ] صُنف كل بند: برنامج رسمي، نشاط داعم، خدمة حدثية، أو عمل مستمر (E04).
- [ ] مسار نور المتوقع مذكور دون ادعاء تنفيذ أو اختراع حقول، أو سُجل أنه غير مطلوب بسبب (N01).
- [ ] لا توجد قيمة مؤشر متوقعة أو نسبة مختلقة؛ الحالة `PENDING/NOT_MEASURED` عند الحاجة (N03).
- [ ] الشاهد المتوقع منفصل عن الشاهد الفعلي، والأثر ليس صورة أو رسالة تلقائيًا (V01).
- [ ] اختير الحد الأدنى من الشواهد الذي يحقق متطلب المصدر (V02).
- [ ] الخطة العامة وGit خاليان من البيانات الحساسة والنسخ المعبأة (P01).
- [ ] الدور النظامي للجنة محفوظ دون افتراض اجتماع أو تنفيذ جماعي (C01).
- [ ] لا سجل ورقي موازٍ؛ وكل استثناء ورقي له نوع وسبب ومصير (D01).
- [ ] حالات نور الأربع متاحة: لم يدخل، أُدخل، تحقق ظهوره، غير مطلوب (D02).
- [ ] توجد أولوية تقدم واحدة مع مسارات تشغيلية وحدثية لازمة دون تشتيت (W01).
- [ ] كل حقل يخدم قرارًا أو متطلبًا أو نورًا أو شاهدًا أو مؤشرًا أو إغلاقًا (W02).
- [ ] خطوة أولى صغيرة وعوازل وثوابت وخطة يوم سيئ مناسبة للأسبوع (W03).
- [ ] أثر التدقيق مرتبط ببصمة الخطة ونسخة المراجع (D04).

## PRE_EXECUTION

- [ ] قرئ دليل البرنامج عند بدء برنامج رسمي، وتحققت الفئة والمتطلبات والشواهد المطلوبة (E01، E02، V02).
- [ ] حسم أي غموض تاريخي يؤثر في الاستحقاق (E03).
- [ ] حدد الإجراء المتوقع في نور دون اختياره كمنفذ (N01).
- [ ] حدد موطن حفظ الأصل الموقع أو النموذج الحساس ومصير ورقة الالتقاط (D01، D03).
- [ ] المهمة قابلة للتنفيذ بواسطة موجه واحد مع الأعمال الإلزامية والطوارئ (W01، W03).

## POST_EXECUTION

- [ ] لا تسجل `نفذ` ولا عدد مستفيدين إلا من الواقعة الفعلية (N02).
- [ ] القيمة الواقعية للمؤشر مسجلة، أو الحالة `NOT_MEASURED/PENDING` دون اختلاق (N03).
- [ ] الشاهد الفعلي مؤرخ ومناسب، والأثر منفصل عند توفر قياس (V01، V02).
- [ ] سجل الإجراء أو الخدمة الفعلية فقط، وحالة نور الحالية دقيقة (N01، D02).
- [ ] لا تنسب واقعة للجنة أو الحضور دون دليل (C01).
- [ ] حفظت الأصول الحساسة خارج Git (P01، D03).

## CLOSURE

- [ ] حالة نور النهائية مميزة: لم يدخل، أُدخل، تحقق ظهوره، أو غير مطلوب (D02).
- [ ] لم يعتبر الإدخال وحده تحققًا من الظهور (D02).
- [ ] حُفظ الأصل الموقع أو أتلف الالتقاط المؤقت بأمان إذا لم يكن أصلًا أو شاهدًا مطلوبًا (D01، D03).
- [ ] لا يوجد شاهد أو تقرير مكرر بلا وظيفة (V02، D01).
- [ ] أُغلقت المهمة أو فُتحت متابعة لاحقة بسبب واضح، دون إعادة البرنامج كبرنامج جديد (E04، W01).
- [ ] اكتمل أثر التدقيق والبصمات والمراجع (D04).

## توثيق المراجعة

- [ ] `rule_id`
- [ ] `phase`
- [ ] `result`
- [ ] `information_status`
- [ ] `evidence_type`
- [ ] `claim`
- [ ] `locator.path`
- [ ] محدد موضع مكتوب النوع: `pdf_page` أو `printed_page` مع خريطته المرتبطة ببصمة الأصل، أو `section` قابل للفحص، أو `paragraph` و`text` في DOCX.
- [ ] وجود المصدر والموضع منفصلان عن دعم الادعاء، وتعذر التحقق أو OCR لا يسجل نجاحًا آليًا.
- [ ] `reviewed_by`
- [ ] `reviewed_at`
- [ ] سبب ونطاق غير المنطبق، إن وجد
- [ ] النتيجة مرتبطة بكامل assessment وبصمات القواعد والفاحص وإصداره والمرحلة والمراجع والمدخلات؛ أعيد فحصها قبل الجاهزية.
- [ ] المرجع الإجرائي هو الأصل الكامل المعتمد؛ المقتطف القديم تاريخي أو مساعد في حدوده.

## سؤالا الواقعية

- [ ] هل يمكن لموجه واحد التنفيذ والإغلاق دون إهمال الغياب والحالات والطوارئ والمواعيد الرسمية؟
- [ ] هل يوجد سبب وموعد لكل التزام مرحل في موطنه، دون إسقاط واجب بسبب حد الصفحة؟
